### 0.1 Claude Code —— 自动记忆（auto memory）

| 维度 | 做法 | 对我们的启示 |
|---|---|---|
| **分类** | 4 类，写入 frontmatter `type`：`user`（角色/偏好）/ `feedback`（纠正与确认）/ `project`（在办/决定）/ `reference`（外部信息在哪） | **我们的 `memoryType` 自由字符串应收敛为标准分类** |
| **写入时机** | **不是每个 turn 都存**——"judges whether the info would be useful in a **future conversation**" | 🔴 **修正我的初版**（见 §3） |
| **跳过** | 能从代码库推导的（架构/路径/debug 修复）、CLAUDE.md 已有的 | 提取要有**负向清单**，别存噪音 |
| **分级加载** | `MEMORY.md` 索引（**前 200 行 / 25KB** 每次加载）+ 主题文件**按需读** | **渐进式披露**：索引常驻、详情按需 |
| **超限** | 写入成功但**报错要重写索引**（超出部分下次加载被丢） | 索引**有硬预算**且必须显式维护 |
| **压缩** | `compact_boundary` 事件；**压缩前注入提醒去写记忆** | 压缩点是记忆沉淀的**天然锚点** |

### 0.2 Codex CLI —— 压缩与"约束固定"

| 维度 | 做法 | 对我们的启示 |
|---|---|---|
| **Constraint Pinning** | `AGENTS.md` **每 turn 从磁盘重读**，**在压缩边界之外**，永不被压缩掉 | 🔴 我们的**手册/系统提示/Agent Contract 必须 pin 在压缩边界外**（初版完全没考虑） |
| **压缩阈值** | 建议 **60%**（不是等到满）——给摘要器留 headroom，避免流断开 | 我们 `contextConfig` 有 0.5/0.7/0.9 三级，接近但需确认触发语义 |
| **压缩策略** | **保留工具结果 + 错误消息，压缩叙述性推理** | 压缩必须**按类型取舍**，不是无差别摘要 |
| **可自定义** | `compact_prompt` 定制摘要指令 | 压缩提示应可配（对标 `CLAUDE.md` 的 Compact Instructions 段） |
| **环境上下文增量** | 只发**变化**的字段（CWD/git 分支/文件差异），不每轮重发整套 | 长会话省 token 的关键手法 |

**Codex 的四原则**（可直接内化）：**Write**（写出去，别留在窗口）·**Select**（按需拉进来）·**Compress**（只留重要的）·**Isolate**（subagent 隔离上下文）。

### 0.3 OpenClaw —— 三层文件 + **压缩前 flush**

| 维度 | 做法 | 对我们的启示 |
|---|---|---|
| **文件分层** | `USER.md`（稳定偏好，小预算）/ `MEMORY.md`（长期 durable facts）/ `memory/YYYY-MM-DD.md`（**每日工作层，append-only**，读**今天+昨天**） | **短期记忆用"日志"而非"全部历史"**；长期用"精炼层" |
| **自动 flush** | **会话接近压缩时**触发**静默 agentic turn**（`NO_REPLY` 用户无感）提醒写记忆；`reserveTokensFloor` + `softThresholdTokens` | 🔴 **这是提取时机的正解**（见 §3） |
| **dreaming sweep** | 后台整合：把 daily notes **蒸馏**进 `MEMORY.md` | **两级沉淀**：日常日志 → 定期蒸馏为长期 |
| **偏好变更** | **原地 supersede**，不 append 矛盾条目 | 印证我们的**演化（⑤）**设计 |
| **明确边界** | "**不该记住它能触及的一切**"——任务状态 / 已验证事实 / 偏好 是**不同东西**，不该共享一个未分化的记忆 | 印证**分类 + 分层**是必须的 |
| **向量检索** | 可插拔（内置 sqlite-vec / QMD / Mem0 / Supermemory） | 我们对应物 = **capm**（替掉它的插件位） |

## 1. 问题重定位：不是"存储弱"，而是"**闭环是断的**"

按代码事实逐条核对（非照抄文档）——**记忆四条边断了三条**：

| 环节 | 代码事实 | 状态 |
|---|---|---|
| **读** | `MemoryResolver`→`listActiveMemoryEntriesByScopes`（`memory-queries.ts:727`）：**只按 `updatedAt DESC`，签名里没有 query** | 🔴 接了但**语义为零** |
| **写** | `POST /gateway/memory-candidates` 全链路完备（policy/幂等/candidateKey）——**全仓无消费方**，runtime 从不产候选 | 🔴 **无人触发** |
| **演化** | `MEMORY_STATES` 有 `superseded`，**全仓无人写入** | 🔴 **无演化** |
| **遗忘** | `MemoryEntry.expiresAt` 三处写入点**恒为 `null`**；检索的过期判断**永远真** | 🔴 **恒不过期** |

**结论**：**有骨架、无生命**。P2 = **接上闭环并让它运转**。

## 2. 目标架构：六步闭环

```
   ①提取 ──→ ②决策 ──→ ③存储 ──→ ④检索
      ↑                              │
      └── ⑥遗忘 ←── ⑤演化 ←─────────┘
```

| 步 | 职责 | 归属 | 对标 |
|---|---|---|---|
| ①提取 | **在压缩点/静默 flush 时**抽原子事实 | nexharness | **OpenClaw flush** |
| ②决策 | 新事实 vs 相似旧记忆 → ADD/UPDATE/DELETE/NOOP | nexharness | Mem0 update |
| ③存储 | 本地结构化 truth + **索引进 capm** | 本地 truth + capm index | — |
| ④检索 | capm 三路召回 + 本地 scope/时效过滤 | **capm** | Mem0 / Graphiti hybrid |
| ⑤演化 | 矛盾不删：旧条标 `superseded` + 双时态 | nexharness | **Graphiti** |
| ⑥遗忘 | TTL → archive（不物理删）+ 事后撤销 | nexharness | Mem0 遗忘 |

## 3. ⭐ 提取时机（按你的第 2 点重新设计）

**你的要求**：默认开启，但**不必每 turn 抽取**——看优秀项目怎么平衡。

**三家给的答案一致**：

| 项目 | 时机 | 机制 |
|---|---|---|
| Claude Code | **按需判断**（"未来对话是否有用"）+ **压缩前提醒** | 压缩边界 + 主动判断 |
| Codex | 压缩点（60% 阈值早触发） | `compact_prompt` |
| **OpenClaw** | **压缩前静默 flush**（`NO_REPLY`，用户无感） | `reserveTokensFloor` + `softThresholdTokens` |

**我们采纳"**压缩前 flush**"为主 + 显式触发为辅**：

| 触发 | 何时 | 说明 |
|---|---|---|
| **主：压缩前 flush** | 会话 token 越过 `contextWindow - reserveTokensFloor - softThresholdTokens` | 触发**静默**提取 turn；用户不可见；一次压缩周期一次 |
| **辅：显式"记住这个"** | 用户/Agent 显式要求 | 立即写，不等压缩 |
| **辅：会话/任务终结** | thread 结束、job 完成 | 收口提取（对标 OpenClaw daily log） |
| ~~每 turn~~ | — | ❌ **废弃**（噪音大、成本高） |

**成本对比**：每 turn 抽取 = N 次 LLM 调用/turn 数；压缩前 flush = **1 次/压缩周期**（通常 1 次/几十 turn）。

**两级沉淀**（对标 OpenClaw dreaming）：
```
压缩前 flush → 当日工作层（原始、明细）
     ↓ 定期/后台蒸馏
长期精炼层（去重、合并、标失效）
```

## 4. ⭐ Constraint Pinning（初版遗漏的关键）

**Codex 的核心洞察**：`AGENTS.md` 每 turn 重读、**在压缩边界外**，因此**永不被压缩掉**。

**我们的对应物必须 pin**：
- Agent Contract / 系统提示 / 工具 schema（能力边界）
- 手册类硬约束（如"发邮件前必须确认"）
- **安全/权限规则**

**做法**：压缩**不处理**这些来源（它们每 turn 从源头重装），只压缩**对话历史**。否则会出现 Codex 论文里的 **Governance Decay**（治理约束被压掉 → 违规率 30–59%）。

## 5. 数据模型改造（可增删）

### 5.1 `MemoryEntry` 增字段

```sql
-- 双时态（对标 Graphiti）
invalidAt            datetime(3)  NULL  -- 事实在现实世界失效（event time）
expiredAt            datetime(3)  NULL  -- 系统标记取代（system time）
-- 演化链（不物理删）
supersedesEntryId    varchar(36)  NULL  -- 取代了哪条
supersededByEntryId  varchar(36)  NULL  -- 被哪条取代
-- capm 索引引用
indexedRevisionRef   varchar(512) NULL  -- capm 侧 document@revision
-- 相关性（晋升/降权，对标 Mem0 retrieval_count）
retrievalCount       int          NOT NULL DEFAULT 0
lastRetrievedAt      datetime(3)  NULL
-- 提取批次（对标 Mem0 history）
extractionRunId      varchar(36)  NULL
-- 记忆分类（收敛为受控值，对标 Claude Code 4 类 + 我们的 decision）
memoryCategory       varchar(32)  NOT NULL DEFAULT 'project'
```

**`memoryType` → `memoryCategory` 收敛**（受控枚举）：
`user`（角色/偏好）· `feedback`（纠正/确认）· `project`（在办/决定）· `reference`（外部信息位置）· `decision`（架构/技术决定）

### 5.2 新增表

| 表 | 用途 | 对标 |
|---|---|---|
| `MemoryExtractionRun` | 提取批次留痕（invocation/thread/源范围 hash/抽取数/决策） | Mem0 history |
| `MemoryDailyLog`（可选） | 当日工作层（append-only，明细）→ 蒸馏进 MemoryEntry | **OpenClaw daily log** |

### 5.3 索引

- `(tenantId, scopeType, scopeRef, memoryState)` — 检索主路径
- `(tenantId, invalidAt)` / `(tenantId, supersededByEntryId)` — 时效 / 演化链
- `entryKey` 唯一（去重）保留

## 6. 分层职责重划

| | nexharness（记忆**生命周期与治理**） | capm（记忆**语义检索与图谱**） |
|---|---|---|
| 内容 | 结构化 truth + 生命周期（scope/state/TTL/演化/分类） | 向量 + 关键词 + 图谱索引 |
| 理由 | 提取时机、决策、作用域、演化、审计、**Constraint Pinning** —— 都是 agent-harness 运行时语义 | embedding/向量/图谱 —— capm 已是权威 |
| 边界 | **不建向量/图谱设施**（守 D2/§2.4） | **不定义记忆生命周期** |

跨边界对齐：本地 `MemoryEntry.contentHash` ↔ capm `document revision`（沿用 `document:revision:chunk`）。
